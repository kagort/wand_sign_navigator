# Путеводитель по книге "Блуждающие значения" — пилот

## Куда что кладём

Проект живёт **внутри вашего основного хранилища**, отдельным vault не является.

- Папку `wilson-guide/` целиком перенесите в любое место основного хранилища (например, в корень или в папку проектов).
- Файл `wilson-card-template.md` из папки `for-shared-templates/` перенесите в вашу общую папку шаблонов (ту, что уже указана в настройках Templater: Settings → Templater → Template folder location).

После переноса структура внутри хранилища будет выглядеть так:

```
<ваше хранилище>/
├── <ваша папка шаблонов>/
│   └── wilson-card-template.md
└── wilson-guide/              ← можно переименовать, если хотите другое имя
    ├── 00-meta/
    ├── 01-concepts/
    ├── 02-metaphors/
    ├── 03-people/
    ├── 04-chapters/
    ├── 05-index/
    └── README.md
```

Папки `00-meta`…`05-index` намеренно с цифровыми префиксами и специфичным содержимым (карточки понятий, а не заметки другого рода) — это снижает риск, что они перемешаются с остальными заметками хранилища при поиске/сортировке.

## Как работать в Obsidian

1. Templater уже настроен на уровне хранилища — отдельно ничего включать не нужно.
2. Чтобы при создании заметки в `wilson-guide/01-concepts/` шаблон подставлялся автоматически: Settings → Templater → **Folder templates** → добавить пару (папка `wilson-guide/01-concepts`, шаблон `wilson-card-template`). Иначе просто выбирайте его вручную через "Create new note from template".
3. Новую карточку понятия сохраняйте в `wilson-guide/01-concepts/`, заполняйте поля по ходу чтения главы.
4. На каждую главу — одна хаб-заметка в `wilson-guide/04-chapters/` (см. пример `glava-02.md`).

## Про публикацию через Quartz (важно при таком расположении)

Раз проект теперь лежит внутри основного хранилища вместе с личными заметками, при настройке Quartz **не указывайте всё хранилище как content-папку** — иначе на сайт попадёт всё остальное. Нужно:

- либо в `quartz.config.ts` в разделе `ignorePatterns` явно исключить всё, кроме `wilson-guide/`;
- либо (проще и надёжнее) не копировать всё хранилище, а копировать/симлинкать в `content/` репозитория Quartz только саму папку `wilson-guide/` — тогда личные заметки физически не попадают в публикуемый репозиторий.

Второй вариант безопаснее — меньше риск случайно опубликовать личное.

```bash
# пример: копируем только проектную папку в content/ репозитория Quartz
cp -r /путь/к/хранилищу/wilson-guide/* /путь/к/quartz-site/content/
```

Можно оформить это шагом в скрипте деплоя (или git submodule/symlink, если хотите, чтобы изменения в хранилище сразу подхватывались).
